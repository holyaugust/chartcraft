# 文档编辑使用引导设计

日期：2026-10-03

## 目的

新用户不知道文档编辑从哪开始。在现有五步流程（准备文档、结构梳理、智能校对、智能排版、导出 Word）上增加三种引导，都从「使用引导」菜单打开，进入页面时不自动弹出。

成功标准：

- 用户能自己打开分步引导、下一步清单或示例演练。
- 三种引导讲的是同一份五步说明。
- 示例演练使用真实按钮；退出、改选其他引导、离开文档编辑或刷新后，回到进入演练前的稿。
- 演练内容不留在正式草稿里。

## 使用方式

入口在「文档编辑」标题右侧，按钮文案为「使用引导」。菜单三项：分步引导、下一步清单、示例演练。

引导状态只有四种：关闭、分步引导、下一步清单、示例演练。同时只处于一种。再次点当前项则关闭。正在演练时，关闭或改选都会先恢复原稿。

### 分步引导

按五步顺序讲解，聚光灯指向当时看得到的控件。每步有短说明，以及下一步、跳过、关闭。不修改正文，不自动切换流程步骤。

目标不在页面上时，显示该步的替代说明。下一步、跳过、关闭仍然可用。窗口滚动或改变尺寸时，高亮跟着目标元素。

「准备文档」在没有正文时指向空状态的三张卡片（AI 写文书、上传 Word、套用模板）。已有正文时指向流程条上的「准备文档」。演练中不把步骤切到「准备文档」，避免现有空状态盖住正文。

### 下一步清单

编辑区旁一张可关闭的卡片。内容来自当前流程步骤：现在做什么、怎样算做完。用户切换流程步骤时，卡片跟着变。

完成信号：

| 步骤 | 算做完 |
|------|--------|
| 准备文档 | 正文非空 |
| 结构梳理 | 已有与当前正文指纹匹配的结构分析结果 |
| 智能校对 | 本轮校对已完成 |
| 智能排版 | 排版完成标记与当前正文指纹一致 |
| 导出 Word | 无持久完成标记；清单说明点「导出文件」并选择一种格式即可 |

### 示例演练

进入前收起当前编辑状态，编辑区换成一份短会议通知。稿内有一处明显错字（「准是参加」）和一处待填（「【联系人】」）。演练从「结构梳理」开始，示例正文在编辑区可见。

顶栏显示「演练中」和「退出并恢复原稿」。梳理、校对、排版、导出使用现有按钮。演练中导出的文件是这份示例通知，文件可以留在磁盘上；编辑区在退出后仍回到原稿。

## 组件

五步说明只放在 `src/data/documentGuideSteps.ts`。每步包含：标识、标题、现在做什么、怎样算做完、聚光灯目标、目标缺失时的说明。

示例通知全文放在 `src/data/documentGuideSample.ts`。

暂存与恢复放在 `src/utils/documentPracticeStash.ts`。引导切换放在 `src/utils/documentGuideMode.ts`。二者都不依赖 DOM。暂存函数接收一个类 Storage 对象，浏览器里传入 `localStorage`。

菜单、聚光灯、清单卡片、演练顶栏放在 `src/components/DocumentGuide.tsx`。样式加在 `src/App.css` 现有文档段落中。

`DocumentWorkspace` 持有引导状态，在流程条、空状态卡片、侧栏主操作和导出按钮上设置 `data-guide` 标记，并负责进入与退出演练。

## 演练快照

换上示例稿之前，先同步写入 `chartcraft-document-practice-stash`。暂存内容是三个正式键的原值（键不存在则记为空）：

- `chartcraft-document-draft`
- `chartcraft-document-structure`
- `chartcraft-document-format-done`

暂存写入成功后，再在内存中保存当前界面，然后才载入示例稿。内存快照包括：正文、流程步骤、校对结果与完成态、结构分析与已应用片段、排版结果与完成态、上传的 Word 缓冲与文件名、内容来源、侧栏、视图、模板、高亮与撤销记录。进入演练时关闭写文书、模板、校对方案等弹窗。

演练期间示例稿继续使用现有自动保存。正式键里可以暂时是示例内容，暂存键保持不动。

恢复分两种：

- 同一次打开内退出（点退出、关闭引导、改选其他引导）：用内存快照还原界面，把暂存写回三个正式键，删除暂存。
- 刷新、重新打开文档编辑，或离开文档编辑页导致工作区卸载：在读取正式草稿之前，把暂存同步写回三个正式键并删除暂存。卸载时的写回放在 effect cleanup 里同步完成，不依赖 setState。校对结果今天不进本地存储，刷新后需要重新校对。

离开文档编辑后再进入其他会读取 `chartcraft-document-draft` 的功能时，读到的是原稿。

`loadDocumentDraft` 在读取正式正文键之前调用恢复。同一次调用里写回结构键和排版完成标记，保证随后的结构加载读到的是原稿。

## 失败处理

`beginPracticeStash` 在写入成功时返回 `{ ok: true }`，失败时返回 `{ ok: false }`。失败时不载入示例稿，编辑区保持原稿，并提示「暂时无法开始演练」。

恢复写回失败时，保留暂存键，提示原稿尚未恢复。下次打开文档编辑再试。暂存 JSON 无法解析时，不覆盖三个正式键，保留暂存并提示。

演练中的梳理、校对、排版失败时，沿用这些面板现有的错误提示，演练顶栏保持显示。每次进入演练分配一个序号。退出或改选之后，序号变化；仍在返回的结果若序号不一致，则丢弃，不写入已恢复的原稿。

## 验证

用可重复运行的脚本检查纯函数。改选其他引导时直接恢复原稿，不另弹确认框。脚本断言：

- 从演练改选其他引导时，结果标明必须先恢复原稿，新状态为所选引导。
- 再次选择当前引导则变为关闭；当前若是演练，结果同样标明必须恢复原稿。
- `beginPracticeStash` 写入失败时返回 `{ ok: false }`。
- 正式键被改写后，恢复能还原原值并删除暂存。
- 损坏的暂存不覆盖正式键。
- `isStalePracticeResult(activeEpoch, resultEpoch)` 在序号不一致时返回 true。

脚本放在 `scripts/check-document-guide.ts`，用 `node --experimental-strip-types scripts/check-document-guide.ts` 运行，不新增测试框架。`npm run build` 必须通过。

浏览器中确认：菜单三项互斥；聚光灯的下一步、跳过、关闭，以及目标缺失时的替代说明；清单随流程步骤变化；演练载入示例通知；退出和刷新后正文、结构存储和排版完成标记回到进入前。

## 范围

只做文档编辑这一种引导。不自动弹出，不做预制的假校对结果，不改其他工作区的交互。不在本功能里修复「回到准备文档会盖住已有正文」；演练通过停在「结构梳理」避开该行为。
